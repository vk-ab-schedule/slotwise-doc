# **Пользовательские сценарии SlotWise**

**Статусы:**

MVP — входит в обязательный объём;

После MVP — запланированное расширение;

Требует решения — функция не должна попадать в разработку, пока команда не согласует её поведение.

# **Словарь терминов**

| Термин | Определение |
| :---- | :---- |
| Учётная запись | Данные для входа конкретного пользователя. |
| Роль | Набор разрешённых действий: администратор, организатор, преподаватель или студент. |
| Область доступа | Сессии, группы и записи, которые пользователь вправе видеть и изменять. |
| Сессия планирования | Контейнер с периодом проведения, событиями, участниками, ресурсами, сроком сбора занятости, правилами и вариантами расписания. |
| Окно сбора доступности | Период, в течение которого приглашённые участники указывают свои занятые интервалы для будущего периода проведения событий. |
| Занятый интервал | Время, когда участие невозможно или нежелательно. Для интервала указывается уровень важности. |
| Уровень важности | Сила ограничения: критический интервал нельзя нарушать, средний желательно сохранить, низкий учитывается как предпочтение. |
| Доступное время | Неотмеченное время внутри периода проведения событий после учёта загруженного расписания и занятых интервалов пользователя. |
| Событие | Единица планирования с длительностью, участниками и требованиями, например консультация или защита одного студента. |
| Тип события | Заготовка со значениями по умолчанию: длительностью, ролями участников, ресурсами и зависимостями. |
| Ресурс | Аудитория или онлайн-площадка с доступностью, вместимостью и оборудованием. |
| Назначение | Предложенные для события дата, время, ресурс и состав комиссии, если она нужна. |
| Вариант расписания | Результат одного расчёта на определённой версии данных и правил. |
| Фиксация | Запрет изменять назначение при следующем расчёте. Фиксация не публикует событие. |
| Публикация | Подтверждение расписания, после которого участники видят свои назначения. |
| Сценарий «что если» | Копия исходных условий для эксперимента без изменения рабочего расписания. |

# **1 Доступ и пользователи**

## **UX-01 Войти в систему**

**Статус:** MVP

**Участник:** Любой пользователь

**Цель:** Получить доступ к функциям и данным своей роли.

**Предусловия:** Учётная запись создана и активна.

**Основной сценарий**

1\. Пользователь вводит данные учётной записи.

2\. Система проверяет данные и определяет роль и область доступа.

3\. Система открывает доступный пользователю раздел.

**Результат:** Пользователь вошёл в систему и видит только разрешённые данные.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Введены неверные данные. | Показать сообщение об ошибке без раскрытия сведений об учётной записи. |
| Учётная запись отключена. | Не выполнять вход и предложить обратиться к администратору. |
| Сессия входа истекла. | Запросить повторный вход. |

## **UX-02 Добавить администратора**

**Статус:** MVP

**Участник:** Действующий администратор

**Цель:** Передать административные полномочия ещё одному участнику команды.

**Предусловия:** В системе есть хотя бы один действующий администратор.

**Основной сценарий**

1\. Администратор создаёт новую учётную запись или выбирает существующую.

2\. Назначает роль администратора и проверяет данные.

3\. Подтверждает выдачу полномочий.

**Результат:** Новый администратор может войти и управлять пользователями.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Указанные данные уже используются (в случае добавления нового пользователя). | Показать существующую учётную запись и предложить изменить её роль. |
| Сохранение не удалось. | Не менять права и показать возможность повторить операцию. |

## **UX-03 Изменить роль и область доступа**

**Статус:** MVP

**Участник:** Администратор

**Цель:** Выдать пользователю нужные полномочия, изменить их или отключить доступ.

**Предусловия:** Учётная запись пользователя существует.

**Основной сценарий**

1\. Администратор находит пользователя и просматривает текущие права.

2\. Выбирает роль и доступные сессии, группы или записи.

3\. Проверяет изменения и сохраняет их.

**Результат:** Пользователь получает обновлённые права; изменение фиксируется в истории администрирования.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Пользователь пытается повысить свои права. | Отклонить запрос; изменение ролей доступно только администратору. |
| Выбрана роль без необходимой области доступа. | Не сохранять неполную настройку и указать обязательные данные. |
| Права изменены во время активной работы пользователя. | Применить новые права к следующим запросам и закрыть ставшие недоступными данные. |
| Операция оставит систему без администратора. | Заблокировать отключение последнего действующего администратора. |

## **UX-04 Добавить пользователей из CSV-файла**

**Статус:** MVP

**Участник:** Администратор

**Цель:** Добавить в систему новых студентов, преподавателей и организаторов без ручного создания каждой учётной записи.

**Предусловия:** Администратор вошёл в систему и подготовил CSV-файл по шаблону системы.

**Основной сценарий**

1\. Администратор открывает раздел управления пользователями и загружает CSV-файл.

2\. Система проверяет структуру файла и показывает предварительный результат: новые записи, совпадения с существующими пользователями и строки с ошибками.

3\. Администратор исправляет или исключает ошибочные строки и подтверждает импорт.

4\. Система создаёт пользователей и сохраняет указанные в файле роли, учебные группы и другие разрешённые связи.

**Результат:** Новые пользователи созданы и доступны для входа в систему и выбора в сессиях планирования.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| В файле отсутствуют обязательные столбцы или использован неверный формат. | Не выполнять импорт; показать список ошибок и ссылку на актуальный шаблон CSV. |
| Строка совпадает с существующим пользователем. | Не создавать дубликат; показать совпадение и предложить пропустить запись или обновить разрешённые поля. |
| Ошибки есть только в части строк. | Показать все проблемные строки и выполнить частичный импорт только после явного подтверждения администратора. |
| Файл пуст или не содержит новых данных. | Не запускать импорт и сообщить, что подходящих записей не найдено. |

# **2 Подготовка планирования**

## **UX-05 Создать сессию планирования**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Задать общие границы работы: когда должны пройти события и когда участники должны сообщить о своей занятости.

**Предусловия:** Организатор вошёл в систему; пользователи и основные справочники уже доступны.

**Основной сценарий**

1\. Организатор задаёт название сессии, период проведения событий, часовой пояс и рабочие часы.

2\. Указывает начало и окончание окна сбора доступности. Оно должно завершиться до начала периода проведения событий.

3\. Сохраняет сессию как черновик и переходит к добавлению событий, участников, ресурсов и правил.

**Результат:** Создан черновик сессии с периодом проведения событий и сроками сбора данных о занятости.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Период проведения событий не задан или дата окончания раньше даты начала. | Не сохранять сессию и подсветить неверные поля. |
| Окно сбора заканчивается после начала периода проведения событий. | Предложить изменить сроки и не открывать сбор до исправления. |
| Сессия с таким названием уже существует. | Разрешить сохранение только после уточнения названия либо явного создания копии. |

## **UX-06 Подготовить учебные связи и ресурсы**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Подготовить учебные группы, связи между участниками, аудитории и другие ресурсы для планирования.

**Предусловия:** Сессия планирования создана.

**Основной сценарий**

1\. Организатор выбирает нужных пользователей и учебные группы из справочников системы.

2\. Проверяет и при необходимости уточняет связи: студент — группа, студент — руководитель, преподаватель — дисциплина или комиссия.

3\. Добавляет аудитории и другие ресурсы, указывает их вместимость, оборудование и ограничения по времени.

**Результат:** В сессии подготовлены участники, учебные связи и ресурсы, которые можно назначать событиям.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Нужного пользователя нет в системе. | Показать, что добавление учётных записей выполняет администратор через импорт CSV. |
| В учебных связях есть противоречия или пропуски. | Показать проблемные записи и не использовать их автоматически до исправления. |
| Ресурс недоступен в пределах всего периода проведения. | Предупредить организатора и предложить заменить ресурс или изменить период. |

## **UX-07 Управлять типами событий**

**Статус:** MVP

**Участник:** Администратор

**Цель:** Создать или изменить заготовку для часто повторяющихся событий.

**Предусловия:** Пользователь имеет право управлять соответствующей областью типов.

**Основной сценарий**

1\. Пользователь открывает список типов событий.

2\. Задаёт название, длительность, роли участников, требования к ресурсам, комиссии и зависимостям.

3\. Сохраняет тип.

**Результат:** Тип доступен при создании события и подставляет значения по умолчанию.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Изменяется тип, уже использованный в событиях. | Не менять созданные события автоматически; применить новые значения только к новым событиям. |
| В типе не хватает обязательных параметров. | Не сохранять тип и перечислить отсутствующие параметры. |

## **UX-08 Создать события и определить состав**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Задать все события, которые система должна расположить в пределах выбранного периода.

**Предусловия:** Сессия создана; пользователи, учебные связи, ресурсы и нужные типы событий доступны.

**Основной сценарий**

1\. Организатор выбирает тип и создаёт одно событие или группу однотипных событий.

2\. Выбирает учебные группы или конкретных студентов, преподавателей и других обязательных участников.

3\. Проверяет длительность, формат, требования к аудитории и другим ресурсам, состав комиссии и зависимости между событиями.

4\. Сохраняет события в сессии планирования.

**Результат:** В сессии сформирован полный набор событий и требований для сбора занятости и последующего расчёта.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Для предмета и группы не найден преподаватель. | Показать отсутствующую связь и не подставлять случайного участника. |
| Один человек выбран несколькими способами. | Объединить совпадения и показать человека один раз. |
| Зависимости образуют цикл. | Не сохранять зависимость и перечислить события цикла. |
| Не хватает обязательного участника или требования. | Сохранить только как неполный черновик либо потребовать заполнение перед расчётом. |

## **UX-09 Указать занятые интервалы и их важность**

**Статус:** MVP

**Участник:** Студент; при необходимости преподаватель или другой приглашённый участник

**Цель:** Сообщить системе, когда участие в событиях невозможно или нежелательно.

**Предусловия:** Окно сбора доступности открыто; участник включён хотя бы в одно событие сессии.

**Основной сценарий**

1\. Пользователь открывает календарь на период проведения событий и видит уже известную системе занятость, например занятия из учебного расписания.

2\. Добавляет свои занятые интервалы и указывает для каждого уровень важности: критический, средний или низкий.

3\. Проверяет календарь и отправляет данные. Неотмеченное время в пределах периода считается доступным для планирования.

**Результат:** Занятые интервалы и их важность сохранены; система использует их как ограничения и предпочтения при расчёте.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Занятия из учебного расписания не загрузились. | Показать предупреждение и разрешить пользователю внести критическую занятость вручную. |
| Интервалы пересекаются. | Объединить пересечение и применить к нему наивысший из указанных уровней важности. |
| Интервал выходит за период проведения событий. | Не сохранять часть вне периода и показать допустимые даты. |
| Окно сбора уже закрыто. | Запретить обычное редактирование и предложить отправить запрос о новой недоступности организатору. |

## **UX-10 Контролировать сбор данных о занятости**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Понять, кто уже передал данные и можно ли завершать сбор.

**Предусловия:** Окно сбора доступности открыто или подходит к завершению.

**Основной сценарий**

1\. Организатор просматривает список приглашённых участников и статус заполнения.

2\. Проверяет участников, которые не отправили данные или оставили предупреждения о неполных данных.

3\. При необходимости напоминает участникам о сроке либо корректирует срок сбора до его закрытия.

**Результат:** Организатор понимает полноту входных данных и видит, какие ответы отсутствуют перед расчётом.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Участник не ответил. | Показывать отсутствие ответа отдельно; не считать пользователя доступным в любое время. |
| У участника есть постоянные настройки, но нет ответа на текущий сбор. | Показать, какие сохранённые интервалы будут использованы. |
| Срок сбора изменён. | Обновить срок для участников и не потерять уже сохранённые ответы. |

# **3 Расчёт и публикация**

## **UX-11 Настроить правила и запустить расчёт вручную**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Настроить ограничения и при необходимости получить новый вариант расписания до или после автоматического расчёта.

**Предусловия:** События и ресурсы подготовлены; организатор понимает состояние сбора данных о занятости.

**Основной сценарий**

1\. Организатор просматривает жёсткие ограничения и задаёт приоритеты мягких требований.

2\. Выбирает алгоритм и лимит времени, проверяет сводку входных данных.

3\. Запускает расчёт и наблюдает за его состоянием.

**Результат:** Создан вариант расписания, связанный с версией данных, правил и алгоритмом.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Во входных данных есть явные противоречия. | Показать предпроверку и предложить исправить данные до запуска. |
| Истёк лимит времени, но решение найдено. | Показать найденный вариант и отметить, что оптимальность не доказана. |
| Истёк лимит без решения. | Не называть задачу доказанно невозможной; предложить другой лимит или исправление условий. |
| Расчёт завершился технической ошибкой. | Показать ошибку отдельно от отсутствия допустимого расписания и разрешить повторный запуск. |

## **UX-12 Получить автоматический расчёт после закрытия сбора**

**Статус:** MVP

**Участник:** Организатор и система

**Цель:** Получить предложенное расположение событий без отдельного ручного запуска после окончания сбора данных.

**Предусловия:** Для сессии заданы события, период проведения, правила расчёта и срок окончания окна сбора доступности.

**Основной сценарий**

1\. В назначенный момент система закрывает окно сбора и фиксирует версию входных данных.

2\. Система автоматически запускает расчёт и формирует предложенный вариант расписания.

3\. При следующем входе организатор видит статус расчёта, предложенные назначения и события, которые не удалось назначить.

**Результат:** Организатор получает черновой вариант расписания для проверки; он не публикуется автоматически.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Не все участники отправили данные. | Пометить отсутствующие ответы и действовать по правилу сессии: запустить расчёт или потребовать решения организатора. |
| Расчёт уже был запущен вручную для той же версии данных. | Не создавать дублирующее задание; показать существующий результат. |
| Автоматический расчёт завершился ошибкой. | Уведомить организатора, сохранить входные данные и разрешить повторный ручной запуск. |

## **UX-13 Проверить результат и причины неназначений**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Понять предложенное расположение событий, причины конфликтов и влияние возможных изменений.

**Предусловия:** Расчёт завершён и сохранил результат.

**Основной сценарий**

1\. Организатор просматривает предложенные события в календаре и список неназначенных событий.

2\. Открывает объяснение конфликта: какие участники, занятые интервалы, уровни важности, ресурсы или правила повлияли на результат.

3\. Выбирает событие или возможный новый слот и видит, на каких участников и ограничения повлияет перенос.

**Результат:** Организатор понимает качество предложенного варианта и последствия ручных изменений.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Вариант рассчитан на устаревших данных. | Заметно пометить его и предложить новый расчёт. |
| Точная причина неназначения не установлена. | Сообщить об ограниченной диагностике без утверждения о единственной причине. |
| Сравниваются варианты на разных данных. | Запретить прямое сравнение либо явно показать различия входных данных. |
| Оптимальность не доказана. | Не использовать слово «оптимальный»; показать доступные метрики и gap, если он известен. |

## **UX-14 Исправить и зафиксировать назначение**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Перенести предложенный слот или защитить его от следующего расчёта.

**Предусловия:** Есть рассчитанный вариант расписания.

**Основной сценарий**

1\. Организатор открывает событие и выбирает другой слот, ресурс или состав комиссии.

2\. Система до сохранения показывает новые конфликты и участников, на которых повлияет изменение.

3\. Организатор подтверждает допустимое изменение и при необходимости фиксирует назначение для следующих расчётов.

**Результат:** Допустимая правка сохранена; фиксированное назначение не меняется при следующем расчёте.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Перенос нарушает жёсткое ограничение. | Не сохранять его и показать конкретную причину. |
| Данные изменились после открытия карточки. | Предложить обновить данные и повторить правку. |
| После изменения исходных данных фиксированный слот стал конфликтным. | Показать конфликт и потребовать явного снятия фиксации или исправления данных. |
| Перетаскивание недоступно или неудобно. | Оставить редактирование через обычную форму; drag-and-drop считать дополнительным способом. |

## **UX-15 Опубликовать полное расписание**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Сделать проверенный вариант действующим для участников.

**Предусловия:** Организатор выбрал вариант и проверил назначения и предупреждения.

**Основной сценарий**

1\. Организатор просматривает итоговую сводку.

2\. Подтверждает публикацию полной допустимой версии.

3\. Система помечает версию как опубликованную и открывает участникам их назначения.

**Результат:** Участники видят действующее расписание; черновые варианты остаются скрытыми.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| В расписании есть нарушение жёсткого ограничения. | Заблокировать публикацию и показать затронутые события. |
| Есть неназначенные события. | Явно показать их и запросить подтверждение правила публикации; полная публикация требует согласованного состава. |
| Запрос публикации повторён. | Не создавать дубли уведомлений и не менять номер версии повторно. |

## **UX-16 Опубликовать часть расписания**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Сделать действующими готовые назначения, не дожидаясь решения для всех событий.

**Предусловия:** Есть проверенные назначения, которые можно опубликовать независимо от оставшихся событий.

**Основной сценарий**

1\. Организатор выбирает допустимые назначения и видит, какие события останутся черновыми или неназначенными.

2\. Подтверждает выбранную часть.

3\. Система публикует её и учитывает опубликованные слоты как занятость в следующих расчётах.

**Результат:** Участники видят только опубликованные назначения; остальные остаются черновыми.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Выбранный слот конфликтует с уже опубликованным. | Заблокировать его публикацию и показать конфликт. |
| Повторный расчёт пытается изменить опубликованный слот. | Считать слот защищённым либо запросить явное снятие публикации по согласованному правилу. |
| Повторная публикация отправляет те же уведомления. | Не дублировать уведомления без фактического изменения. |
| Оставшиеся события не удаётся назначить. | Не отменять опубликованную часть автоматически; показать проблему организатору. |

# **4 Работа после публикации и развитие**

## **UX-17 Посмотреть своё расписание**

**Статус:** MVP

**Участник:** Студент или преподаватель

**Цель:** Узнать актуальные время, место и состав своих событий.

**Предусловия:** Организатор опубликовал расписание.

**Основной сценарий**

1\. Пользователь открывает личный календарь.

2\. Выбирает событие и просматривает дату, время, часовой пояс, формат, аудиторию или онлайн-площадку и разрешённые сведения об участниках.

**Результат:** Пользователь знает актуальные сведения о своих событиях.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Назначений нет. | Показать пустое состояние, отличимое от ошибки загрузки. |
| Расписание изменено. | Показать актуальную версию и отметить изменённые события. |
| Студент запрашивает чужое расписание. | Не предоставлять данные другого студента. |
| Часть сведений ограничена правами. | Показать только данные, необходимые пользователю для участия. |

## **UX-18 Экспортировать расписание в календарь**

**Статус:** После MVP

**Участник:** Студент или преподаватель

**Цель:** Добавить опубликованные события во внешний календарь.

**Предусловия:** У пользователя есть опубликованные назначения.

**Основной сценарий**

1\. Пользователь выбирает экспорт своего расписания.

2\. Система формирует ICS с корректными часовыми поясами.

3\. Пользователь скачивает файл и импортирует его во внешний календарь.

**Результат:** События доступны во внешнем календаре.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Опубликованных событий нет. | Не создавать пустой файл без объяснения; показать причину. |
| Расписание изменилось после скачивания. | Предупредить, что файл не обновляется автоматически и требуется повторный экспорт. |
| Повторный импорт создаёт дубли. | Добавить стабильные идентификаторы событий и описать рекомендуемый способ обновления. |

## **UX-19 Сообщить о новой недоступности или запросить перенос**

**Статус:** MVP

**Участник:** Студент или преподаватель

**Цель:** Сообщить, что пользователь больше не может участвовать в назначенное время.

**Предусловия:** Расписание опубликовано либо окно обычного редактирования доступности закрыто.

**Основной сценарий**

1\. Пользователь выбирает событие или период недоступности.

2\. Указывает причину и отправляет запрос.

3\. Просматривает статус обращения и действующее назначение до решения организатора.

**Результат:** Организатор получает запрос и список затронутых событий.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Похожий запрос уже открыт. | Показать существующий запрос и не создавать дубликат. |
| Событие уже завершилось. | Не создавать запрос переноса; показать актуальный статус события. |
| Запрос ещё не рассмотрен. | Не скрывать действующее назначение; пометить его как проблемное. |
| Недоступность затрагивает несколько событий. | Показать весь затронутый список до отправки. |

## **UX-20 Частично перестроить расписание**

**Статус:** MVP

**Участник:** Организатор

**Цель:** Найти замену после отмены или изменения условий, сохранив остальные назначения насколько возможно.

**Предусловия:** Есть опубликованная версия и изменение, затрагивающее одно или несколько событий.

**Основной сценарий**

1\. Организатор открывает изменение и проверяет затронутые события.

2\. Запускает перестроение с учётом опубликованных и фиксированных назначений.

3\. Сравнивает предложенную версию с действующей, принимает или отклоняет её и публикует принятые изменения.

**Результат:** Затронутые участники получают новую опубликованную версию; прежняя сохраняется, если предложение отклонено.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Подходящего варианта нет. | Сохранить действующую версию и показать неназначенные события и причины. |
| Фиксация мешает перестроению. | Показать конфликт; снятие фиксации выполнять отдельным подтверждённым действием. |
| Предложение меняет незатронутые события. | Показать эти изменения; в MVP стремиться ограничить область перестроения. |
| Организатор отклоняет предложение. | Не менять опубликованную версию и сохранить результат как черновик при необходимости. |

## **UX-21 Сравнить условия в сценарии “что если”**

**Статус:** После MVP

**Участник:** Организатор

**Цель:** Проверить эффект изменения ресурса, дня или правил без изменения рабочего расписания.

**Предусловия:** Есть исходная сессия и сохранённый вариант расписания.

**Основной сценарий**

1\. Организатор создаёт копию условий и меняет выбранный параметр.

2\. Запускает расчёт сценария.

3\. Сравнивает метрики и назначения с исходным вариантом.

**Результат:** Организатор видит эффект изменения; рабочая сессия не меняется.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Расчёт сценария завершился ошибкой. | Не затрагивать исходную сессию и разрешить повторный запуск. |
| Исходные данные изменились во время эксперимента. | Показать версии данных и предложить пересоздать сценарий. |
| Пользователь хочет применить результат. | Создать отдельный проверяемый вариант; не заменять опубликованное расписание автоматически. |

## **UX-22 Провести и просмотреть эксперимент алгоритмов**

**Статус:** После MVP

**Участник:** Участник команды или организатор с правом эксперимента

**Цель:** Сравнить качество и время работы алгоритмов на воспроизводимых наборах.

**Предусловия:** Доступны синтетические наборы, алгоритмы и параметры запуска.

**Основной сценарий**

1\. Пользователь выбирает наборы, seed, алгоритмы и лимиты времени.

2\. Запускает серию прогонов и видит состояние выполнения.

3\. Просматривает таблицы и графики метрик, сохраняет результаты в CSV.

**Результат:** Получены воспроизводимые данные для сравнения greedy, CP-SAT и дополнительных методов.

**Исключительные ситуации и решения**

| Ситуация | Решение системы или пользователя |
| :---- | :---- |
| Прогоны используют разные входные данные. | Не объединять их в прямое сравнение без явного предупреждения. |
| Отдельный прогон завершился ошибкой. | Сохранить остальные результаты и пометить неуспешный прогон. |
| Результат не проходит единый валидатор. | Исключить его из сравнения качества и показать нарушение. |
| Нет третьего алгоритма. | Разрешить сравнение доступных алгоритмов и не блокировать обязательный эксперимент MVP. |
